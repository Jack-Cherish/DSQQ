# 大肥鱼一键包 设计文档

日期：2026-10-28　状态：草稿，待确认

## 1. 为什么做

教程《把 DeepSeek 养进 QQ：从零教程》（`D:\Coding\test\dafeiyu-astrbot\把 DeepSeek 养进 QQ：从零教程.md`）能把「大肥鱼」跑起来，但要装启动器、下组件、建实例、装 NapCat、建机器人、填 Token、配白名单、跑导入工具，十几个环节，每个都有坑（GitHub 被墙、镜像 403、NapCat 残留文件、Token 对不上）。UP 主的粉丝大多是没装过这些东西的小白，卡在任何一步就放弃了。

一键包要把这些全藏到后台。粉丝只做五件事：**双击、等、填 key、扫码、点掉安全弹窗**。做完马上能在 QQ 里和完整的大肥鱼聊天。

发布方式：放在视频下面公开下载。许可证和封号风险由 UP 主在视频里讲，一键包里只保留一句显眼的「请用小号」提醒。

**用户已明确决定：不考虑许可证。** NapCat、QQ 内核（如果需要）、6 个第三方插件、两套表情包全部直接打进包里，实现方不用为许可证改方案。

## 2. 目标

- 双击一个文件启动，全程图形界面，不出现需要读、需要敲字的黑窗口。
- 用户可以选安装位置。
- 不依赖 GitHub、不依赖翻墙：能打进包里的全打进去（Python 运行环境和依赖、AstrBot、NapCat、配置包、6 个第三方插件、两套表情包）。安装时只连这几个地方：DeepSeek、火山引擎（豆包）、硅基流动（检查 key、运行时用）、腾讯（扫码登录）。
- 装好就是**完整的大肥鱼**：人设、分段回复、表情包、群聊读空气、主动聊天、QQ 空间、改签名、豆包语音、唱歌、长期记忆、防乱码，以及教程第 7 章的「关门」设置（白名单、管理员、电脑能力关闭）。
- 少量个性化：名字、性格、声音、表情包。都有默认值，不改也能直接装。
- 装完以后，桌面有一个「启动大肥鱼」，双击就让她上线；登录还有效时不用再扫码。
- 先检测机器上已有的环境，能复用的复用（范围见 5.4，有一项待确认）。

## 3. 不做什么（非目标）

- 不装 Ollama、不装 Breeze，不提供 Edge / MiMo 语音，不提供「关掉语音」「先不装记忆」这类选项。记忆固定用硅基流动，语音固定用豆包。
- 不做 macOS / Linux，只做 Windows 10/11 x64。
- 不做自动更新。新版本就重新下一个包。
- 不接抖音、B 站、微信。
- 不改本仓库（dafeiyu-astrbot）里那套云端部署（DashScope、Docker、PhoneMCP 等），它只是参考。

## 4. 绝对不能出现的情况（反目标）

做出来能跑，但出现下面任何一条，也算失败：

- 动了用户电脑上已有的 QQ、AstrBot、NapCat 或它们的数据。
- key、Token、后台密码出现在日志、截图区域或报错弹窗里。
- AstrBot 后台、NapCat 后台、OneBot 连接端口对局域网开放（必须只绑 `127.0.0.1`，OneBot 必须带 Token）。
- 用户要看懂黑窗口、去某个文件夹里找文件、手动抄密码。
- 装到一半失败以后，再双击只能报错，没法接着装（必须能从断点续装）。
- 某个 key 填错，要等全部装完、在 QQ 里没回应才发现。

## 5. 用户看到的流程（已确认）

一个窗口里的向导，共 6 页。UI 要比草图美观：配色和字体走「大肥鱼」的蓝色鲸鱼风格，可以用 `dafeiyu-astrbot/assets/avatars/v3-20261025/` 里的立绘当插图。

### 5.1 六页

1. **欢迎 + 安装位置**：一句话介绍；红色提醒「请用 QQ 小号，有被封号风险」；安装路径输入框加「浏览」按钮，默认 `D:\DaFeiYu`（没有 D 盘就用 `C:\DaFeiYu`）。自动检查：路径不能有中文和空格、所在磁盘剩余空间够不够。点「开始安装」后，后台立刻开始解压和安装，后面几页填写时它一直在跑。
2. **填信息**：5 项，全部必填。
   - 你的大号 QQ（只能数字）
   - DeepSeek API key
   - 豆包语音 APP ID
   - 豆包语音 Access Token
   - 硅基流动 API key

   每项旁边有「去哪申请」，点开是图文说明（内容取自教程第 4 章、9.2 节，包括「先点试用、别点开通」「要旧版控制台的 APP ID，不是火山方舟的 key」）。填完一项就在后台检查一次，结果显示为 ✅ / ❌ / ⏳；❌ 要说清是哪种错（key 无效、余额不足、豆包没领试用即 `45000030`、网络不通）。5 项都 ✅ 才能下一步。页面底部一直显示后台安装进度。
3. **个性化**：都有默认值，可以直接下一步。
   - 名字：默认「大肥鱼」。
   - 性格：大文本框，默认是配置包 `persona/大肥鱼.md` 的内容。
   - 声音：豆包 Seed Audio 没有固定音色列表，声音是靠一段文字描述出来的（配置包 `voice.doubao.persona`）。所以这里是一个「声音描述」文本框，默认「一个憨萌软糯的小女生，声音甜甜的、有点奶……」，旁边一个「试听」按钮，用用户的豆包凭证念一句。另给 3 个预设描述可以一键填入（甜妹 / 御姐 / 少年之类，具体文案由实现方写）。
   - 表情包：两个勾选框（蓝色大肥鱼、DeepSeek 二创），至少勾一个；加一个「添加自己的图」，选本地图片加进去。
4. **等安装完成**：清单式进度，每项显示 ✅ / ⏳ / ❌，已有环境被复用的写明「检测到已有 xxx，直接用」。提示「弹出 Windows 安全提示时点允许/运行」。
5. **扫码**：二维码直接显示在窗口里，过期自动刷新。文字「用登着**小号**的手机 QQ 扫一下」。登录成功自动进下一页。
6. **完成**：「她上线了，用你的大号私聊小号说句话试试」。桌面快捷方式「启动大肥鱼」已放好。显示后台地址、账号、密码（同时写进安装目录 `我的信息.txt`），按钮「打开后台」「完成」。

### 5.2 以后每次启动

双击桌面「启动大肥鱼」，打开同一个窗口的「状态页」：后台拉起 AstrBot 和 NapCat，用上次登录的 QQ 号快速登录；登录失效（被踢、风控）就显示二维码让用户重扫。状态页显示「她在线 / 正在启动 / 需要扫码 / 出错了（原因）」，有「让她下线」按钮。关掉窗口不影响她在线；想下线就点按钮，或再次打开状态页点按钮。

同一个状态页里放一个「改设置」入口，能重新改第 3 页的四项和第 2 页的 key（改完自动重新导入，并在 QQ 里提示发 `/reset`）。

### 5.3 中途失败和重装

- 每一步完成就记录到安装目录里的状态文件。安装中断（关窗口、断电、报错）后再双击，检测到这个目录里有没装完的，直接从断点接着装，已填的信息不用重填（key 以加密或至少不明文显示的方式保存，见第 7 节）。
- 失败时页面上给一句人话原因和一个「重试」按钮，不弹堆栈。完整日志写进安装目录 `logs\`，日志里不许出现 key 和密码。

### 5.4 检测已有环境

确定的部分：

- **本一键包之前装过**：同一路径下检测到已装好的一键包，就不重装，直接走 5.2 的启动流程或「修复」。
- **端口**：AstrBot 后台（默认 6185）、OneBot 反向 WS（6199）、NapCat WebUI（6099）被占用时，自动换空闲端口并把两边配置写一致。
- **已有的 QQ、AstrBot、NapCat**：只检测、不使用、不修改。一键包永远用自己目录里那一套，避免把用户原来的机器人覆盖掉。
- **显示窗口用的浏览器内核**：优先用系统自带的 Edge 以「应用窗口」模式打开（没有地址栏），没有 Edge 就用默认浏览器。

- **Python / uv / Node.js**：只用包里自带的，系统里的检测到也不用（用户决定，见第 9 节）。

## 6. 技术方案

以下除特别注明外，都是设计时定下的做法（不是用户逐条拍板的），实现方发现走不通可以换，但要守住第 2、4 节。

### 6.1 发布形式

- 对外只有一个文件：`大肥鱼一键包.exe`，用 7-Zip 自解压模块（SFX）打包。双击后把一个很小的「引导部分」（便携 Python + 向导程序）解到临时目录并启动向导；真正的大文件（payload 压缩包）在用户选好安装路径后才解到那里。
- 未签名的 exe 会弹 SmartScreen「Windows 已保护你的电脑」，这就是用户说的「确认安全弹窗」，向导第 1 页和视频里提示「点更多信息 → 仍要运行」。
- 包里的 `7z.exe` / `7z.dll` 用来解 payload（NapCat 的 OneKey 包里就带了一份，也可以从 7-zip.org 取）。

### 6.2 向导程序

- 用 Python 标准库写一个本机 HTTP 服务（只绑 `127.0.0.1`、随机端口、URL 带一次性 token），页面是普通 HTML/CSS/JS，没有前端构建步骤。
- 用 `msedge --app=<url>` 打开成一个没有地址栏的应用窗口；关掉窗口时向导服务跟着退出（安装进行中则提示「还在安装，确定要退出吗，下次双击会接着装」）。
- 不用 Qt：Python 已经要打进包里，再加 PySide 要多一百多 MB，换来的只是窗口外观。
- 后台安装步骤在向导进程里用线程跑，进度通过轮询接口推给页面。

### 6.3 安装目录结构（建议）

```
D:\DaFeiYu\
  runtime\python\        便携 Python 3.12（python-build-standalone），AstrBot 和插件的依赖预装在里面
  astrbot\               AstrBot 4.29.x 源码 + data\（含 dist 后台页面、插件、表情包、配置）
  napcat\                NapCat（自包含 Shell 模式，见 6.5）
  pack\                  大肥鱼配置包（persona、settings、plugins、tools\import_dafeiyu.py）
  app\                   向导 / 状态页程序
  logs\
  state.json             安装进度和用户选项（不含明文 key）
  我的信息.txt           后台地址、账号、密码
  启动大肥鱼.bat 等      桌面快捷方式指向它（快捷方式用 pythonw 启动，不出黑窗口）
```

### 6.4 AstrBot

- 不用 AstrBot 启动器：启动器的流程是在线下组件、在线装依赖，正是要绕开的部分。直接用便携 Python 跑 AstrBot 的 `main.py`，数据目录放在安装目录里。
- 依赖在**打包时**装进便携 Python（用 PyPI 国内镜像），用户机器上不装任何包。6 个第三方插件和 4 个配置包自带插件的依赖也要在打包时装进去，否则插件首次加载会去 pip 下载。
- 后台账号密码由向导生成（随机强密码），首次启动前写进配置；后台只绑 `127.0.0.1`。
- 平台（OneBot v11，主机 `127.0.0.1`，端口见 5.4，随机 Token）、DeepSeek 提供商（模型 `deepseek-flash`，同时设为对话模型和图片转述模型）由向导通过 AstrBot 的后台接口创建，做法对照教程第 5 章手动步骤。机器人名称保持一个固定的内部 ID，用户改的「名字」只影响人设，不影响会话 ID。

### 6.5 NapCat

- 用**自包含 Shell 模式**（`NapCat.Shell.Windows.Node.zip`，根目录 `napcat.bat` 即 `node.exe index.js`），不注入已安装的 QQ。理由见 `dafeiyu-astrbot/docs/踩坑合集.md` 第 22 条：QQ 9.9.33 在 Win11 25H2 上注入即崩，OneKey 方式会改 `package.json` 也会崩。
- **实现方必须先验证**：这个模式是否真的不需要另装 QQ，需要的话 QQ 内核也打进包里、放在一键包自己的目录。`D:\Coding\test\onekey-dev\downloads\` 里现有的是 `NapCat.Shell.zip` 和 OneKey 包，不是 Node 版，要另取。
- 用无窗口方式启动 NapCat，标准输出写进 `logs\`。
- OneBot 网络配置（WebSocket 客户端，`ws://127.0.0.1:<端口>/ws`，Token 与 AstrBot 一致，心跳和重连 1000ms）和 WebUI token 由向导预先写进 NapCat 的配置文件，不经过 NapCat 网页。登录前不知道 QQ 号，实现方要确认 NapCat 对「还没有 `onebot11_<QQ号>.json`」时的默认配置行为，必要时登录成功后再写入并让它重连。
- 二维码：从 NapCat 的 WebUI 接口或 `cache\qrcode.png` 取，显示在向导页面里。
- 第一次登录成功后记下 QQ 号，以后用快速登录（`napcat.quick.bat` 那种传 QQ 号的方式）。
- NapCat 断线不自愈（踩坑合集第 5 条），状态页常驻时做一个简单的巡检：连不上就重启 NapCat 连接。

### 6.6 大肥鱼配置：复用现成的导入工具

配置包仓库 `github.com/zexuanw958-svg/dafeiyu-config-pack` 的 `tools/import_dafeiyu.py` 已经把人格、插件、插件设置、表情包、记忆、语音、全局设置、白名单、管理员全做了，而且支持非交互的 `--answers 回答.json`，可以反复跑（装过的会跳过）。一键包**直接调用它**，不重写：

- 回答文件里固定 `memory=2`、`voice=3`，填入用户的 QQ 号、硅基流动 key、豆包 APP ID / Access Token、后台地址和账号密码。key 通过 `*_file` 字段指向临时文件，用完删掉。
- 它要求后台里已经有 OneBot 平台和对话模型，所以 6.4 那一步必须先做完。
- 个性化的写入方式：
  - 名字：把人设文本里的「大肥鱼」换成用户填的名字；人设 ID 保持不变。
  - 性格：用户改过的文本直接替换 `persona/大肥鱼.md`，保留 `{OWNER_QQ}` 占位（如果用户删了，就在末尾补一句主人 QQ 号的说明）。
  - 声音：写进 `settings/pack.json` 的 `voice.doubao.persona`。
  - 表情包：改 `settings/pack.json` 里 `meme_packs` 各项的 `use`；用户自己的图通过 meme_manager 插件的接口导入（实现方查它的上传接口）。
- 离线的关键：导入工具的插件和表情包步骤要联网（插件市场、GitHub 加速站）。打包时就在一个干净的 AstrBot 里把 6 个插件装好、两套表情包下好，随 `astrbot\data\` 一起打进去；用户机器上跑导入工具时它会看到「已装过」「已有」直接跳过。打包机上打包前要清掉所有 key、密码、会话记录。
- 导入工具的输出不直接给用户看：向导按它的输出解析每一项 ✔/✘，翻译成第 4 页的清单。实现方可以给它加一个机器可读的结果输出（比如 `--result-json`），只做最小改动。

### 6.7 key 检查（第 2 页）

向导在后台直接发请求，不依赖 AstrBot：

- DeepSeek：列模型或发一句极短的对话，区分「key 无效」和「余额不足」。
- 硅基流动：对 `BAAI/bge-m3` 做一次嵌入。
- 豆包：用 APP ID + Access Token 合成一句极短的话（会花约几分钱，或消耗试用额度），能识别 `45000030`（没领试用 / 没开通服务）。第 3 页的「试听」复用这个调用。

### 6.8 打包流程（给维护者用，不给粉丝）

一个构建脚本，在维护者有网络的电脑上运行，产出 `大肥鱼一键包.exe`：

1. 取便携 Python 3.12、AstrBot 4.29.x 源码和后台页面（`onekey-dev\downloads\` 里已有 `astrbot-src.zip`、`astrbot.zip`）、NapCat 自包含版、配置包。
2. 用国内 PyPI 镜像把 AstrBot 和全部插件的依赖装进便携 Python。
3. 起一个临时 AstrBot，装好 6 个插件、两套表情包，停掉，清理敏感数据，得到干净的 `data\`。
4. 压成 payload，加上引导部分，做成 SFX exe，输出文件大小和 sha256（教程里要给下载者核对）。

版本锁定：AstrBot、NapCat、插件、Python 版本都写死在构建脚本里，升级要人工改版本号再重新验证。

## 7. 安全要求

- 三个端口全部只绑 `127.0.0.1`；OneBot 带 20 位以上随机 Token；NapCat WebUI token 随机。
- AstrBot「使用电脑能力」保持「不允许任何环境」（导入工具已经设置）。
- 白名单只放主人私聊会话，管理员只加主人 QQ（导入工具已经做）。
- `state.json` 里保存 key 时用 Windows DPAPI 加密（Python 可以用 `ctypes` 调 `CryptProtectData`，不加依赖）；`我的信息.txt` 只放 AstrBot 后台账号密码，不放 key。
- 日志写入前过滤所有 key、Token、密码。

## 8. 已知风险

- NapCat 和 QQ 的兼容性随 QQ 版本变化，换个 Windows 版本就可能起不来（踩坑合集第 22 条）。必须在至少两台干净的 Win10 / Win11 上实测。
- 杀毒软件可能拦截 NapCat 的 dll 或未签名的 exe。向导要能识别「文件被删 / 被拦」并提示用户添加信任。
- 新 QQ 小号容易被风控掉线，这不是一键包能解决的，状态页只负责提示重新扫码。
- 包的体积预计几百 MB 到 1GB 以上（实现方打完包给出实际数字）。
